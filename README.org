#+TITLE: org-slideboard: present Org files as slides, in Emacs
#+OPTIONS: toc:2 num:nil ^:{}

org-slideboard shows an Org file as slides inside Emacs.  It is made for
files written for beamer export: beamer columns, equations, tables, macros
and code blocks are shown much as they would be in the PDF, while the text
stays live Org that can be edited, and code that can be run, during the
show.

For a tour, open [[file:demo.org][demo.org]] and run =M-x org-slideboard-start-slideshow=: it is a
presentation about org-slideboard, in which each slide uses the feature it
describes.  It also serves as a template for your own presentations.

* Installation
org-slideboard is not yet on MELPA, so install it from this repository.

With Emacs 30 or later, =use-package= can fetch it directly:

#+begin_src emacs-lisp
(use-package org-slideboard
  :vc (:url "https://github.com/vikasrawal/org-slideboard")
  :commands org-slideboard-start-slideshow)
#+end_src

With Emacs 29, install it once with =M-x package-vc-install RET
https://github.com/vikasrawal/org-slideboard RET=, then use
=(use-package org-slideboard :commands org-slideboard-start-slideshow)=.
=M-x package-vc-upgrade= updates it.

With straight.el:

#+begin_src emacs-lisp
(use-package org-slideboard
  :straight (:host github :repo "vikasrawal/org-slideboard")
  :commands org-slideboard-start-slideshow)
#+end_src

Or clone the repository and add it to the load path:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/org-slideboard")
(require 'org-slideboard)
#+end_src

Once it is on MELPA, =(use-package org-slideboard :ensure t)= will be
enough.

It needs Emacs 28.1 and Org 9.6 or later.  org-modern, ESS and
python-mode are used when installed, but are not required.

org-slideboard does not bind function keys, which Emacs reserves for
users; see [[*Changing the keys][Changing the keys]] to add your own.

* Overview

org-slideboard offers:

- *Beamer columns side by side*: frames with =:BMCOL:= / =:BEAMER_col:=
  children are shown as a title strip above one window per column.
- *Images fitted to the column*: plots are drawn by org-slideboard itself and
  scaled to the width and height of their window.
- *Text size under your control*: all frames of all slides share one text
  size, which ~C-=~ and =C--= change; =C-c }= and =C-c {= (or Emacs's zoom
  keys) change a single frame.  Titles keep their size.
- *Information strip*: a line at the bottom (or top) of every slide with
  author, title, slide number, or whatever you choose.
- *Aligned tables*: tables are aligned to what is displayed, including
  expanded macros, equation images and proportional fonts.
- *Reflowed paragraphs*: hard-wrapped source lines are joined on screen, as
  LaTeX would do.
- *Clutter hidden*: property drawers, =#+NAME:=, =#+RESULTS:=, =#+ATTR_*:=
  lines, non-exported source blocks and raw LaTeX lines are not shown.
- *Equations sized to the text*: LaTeX math is previewed at the size of
  the text and follows it when the size changes, and beamer-only
  =#+LATEX_HEADER:= lines no longer leak into the equation images.
- *Macros expanded*: ={{{macro(...)}}}= is shown as its expansion, and a
  macro can be given its own definition for the show.
- *Code and results*: a slide can show only the results of a source block,
  or the results above its code (or beside it); =C-c C-c= updates the results,
  and editing the block shows it next to a running R or Python REPL.
- *Title page and section pages*: generated (and animated) from =#+TITLE=,
  =#+AUTHOR=, =#+DATE= and from the headings above the slides.
- *Beautification during the presentation only*: org-modern,
  variable-pitch text and hidden emphasis and macro markers are switched on for
  the presentation and turned off afterwards.
- *COMMENT headings skipped*, as in beamer export.

* Preparing a presentation

** Slides
A slide is a heading with the =:slide:= tag.  For a beamer file with
=#+OPTIONS: H:2=, tag every level-2 heading:

#+begin_example
,* Section title
,** Frame title                                                     :slide:
#+end_example

Add =tags:nil= to =#+OPTIONS= so the tag is not printed in the beamer output:

#+begin_example
,#+OPTIONS: toc:nil H:2 tags:nil
#+end_example

To tag all level-2 headings of a file at once, evaluate this in the file's
buffer:

#+begin_src emacs-lisp
(org-map-entries (lambda () (org-toggle-tag "slide" 'on)) "LEVEL=2")
#+end_src

Slides under a =COMMENT= heading (or with =COMMENT= in their own
heading) are skipped, so the presentation has the same frames as the
PDF.  Un-commenting a heading brings its slide back, since it keeps
its tag.

** Columns
Columns are written exactly as for beamer: children of the slide heading with
a =BEAMER_col= property (or the =BMCOL= tag).

#+begin_example
,** Title                                                           :slide:
,*** Left                                                           :BMCOL:
:PROPERTIES:
:BEAMER_col: 0.5
:END:
[[file:image-8.png]]

,*** Right                                                          :BMCOL:
:PROPERTIES:
:BEAMER_col: 0.45
:END:
+ First point
+ Second point
#+end_example

The column widths on screen are proportional to the =BEAMER_col= values.  A
column without a width gets an equal share.  Text between the slide heading
and the first column is shown in a full-width frame above the columns.

** Title page
The title page is made from these keywords:

| Keyword       | Shown as        |
|---------------+-----------------|
| =#+TITLE:=    | title (bold)    |
| =#+SUBTITLE:= | subtitle        |
| =#+AUTHOR:=   | author (italic) |
| =#+DATE:=     | date (italic)   |

LaTeX in these values is tidied up: =\\= starts a new line, =\today= becomes
today's date, =\and= becomes a comma, and other commands are dropped while
their text is kept.  Empty keywords are left out.  Without =#+TITLE=, the
file name is used, as beamer does.

** Section pages
A section page is shown before the first slide under each heading that sits
above the slides, e.g. each level-1 heading when the slides are level-2
headings.  A section whose slides are all commented out gets no page.

* Running the presentation

** Starting and stopping
| Command                                 | Does                                    |
|-----------------------------------------+-----------------------------------------|
| =M-x org-slideboard-start-slideshow=    | start at the beginning (the title page) |
| menu /org-slideboard → Open this slide/ | start at the slide containing point     |
| =M-x org-slideboard-stop-slideshow=     | stop and restore the buffer             |

Stopping removes the column windows and their buffers, un-hides
everything, turns off the beautification modes that the presentation
turned on, and widens the buffer.

Starting and stopping do not change the buffer: the tags of slide headings
are hidden with overlays.

** Keys
During a show, these keys work in the windows of the slides: the title
strip, the frames, and the title and section pages.

| Key       | Command                                  |
|-----------+------------------------------------------|
| =PgDn=    | next slide                               |
| =PgUp=    | previous slide                           |
| =C-c ;=   | show the current slide again             |
| ~C-=~     | larger text in all frames of all slides  |
| =C--=     | smaller text in all frames of all slides |
| =C-c }=   | larger text in the selected frame only   |
| =C-c {=   | smaller text in the selected frame only  |
| =M-ESC g= | go to slide number                       |
| =M-ESC t= | table of contents                        |
| =M-ESC q= | stop the presentation                    |
| =M-ESC 0= | all text sizes back to the start         |

They are not active in other buffers, such as a REPL, another file or the
buffer where a code block is edited, so your own keys keep working there
during the show.  =C-c ;= and =C-c {= / =C-c }= are in the range Emacs
sets aside for minor modes, so they do not clash with =C-c= plus a letter,
which are yours.  Org itself uses them, though (commenting a heading, and
table formula tools); in slide windows the show's keys take precedence.  If
you need those Org commands during a show, or any of these keys clash with
your own, change them as described below.

On a slide with code and results (see [[*Code and results][Code and results]]),
these work in the code window:

| Key       | Command                                                                       |
|-----------+-------------------------------------------------------------------------------|
| =C-c C-c= | run the code and show the new results                                         |
| =C-c '=   | edit the code next to a running REPL (or your own key for =org-edit-special=) |

** Changing the keys
The keys of the show are in =org-slideboard-keys-mode-map=, and those of the
code window in =org-slideboard-code-mode-map=.  To change, add or remove a
key, set it in the map after org-slideboard is loaded:

#+begin_src emacs-lisp
(with-eval-after-load 'org-slideboard
  ;; your own keys for the text size, instead of C-= and C--
  (define-key org-slideboard-keys-mode-map (kbd "C-=") nil)
  (define-key org-slideboard-keys-mode-map (kbd "C--") nil)
  (define-key org-slideboard-keys-mode-map (kbd "<f9>") #'org-slideboard-increase-text-size)
  (define-key org-slideboard-keys-mode-map (kbd "S-<f9>") #'org-slideboard-decrease-text-size)
  ;; function keys
  (define-key org-slideboard-keys-mode-map [f6] #'org-slideboard-execute-slide)
  (define-key org-slideboard-keys-mode-map [f7] #'org-slideboard-next-slide)
  (define-key org-slideboard-keys-mode-map [f8] #'org-slideboard-previous-slide))
#+end_src

A key set to =nil= falls back to your own binding.  With Emacs 29 or later,
=keymap-set= does the same, e.g.
=(keymap-set org-slideboard-keys-mode-map "<f6>" #'org-slideboard-execute-slide)=.
With =use-package=, use =:bind= with =:map=:

#+begin_src emacs-lisp
(use-package org-slideboard
  :bind (:map org-slideboard-keys-mode-map
         ("<f6>" . org-slideboard-execute-slide)
         ("C-c ;" . nil)))
#+end_src

Keys bound globally, e.g. =(global-set-key (kbd "<f5>")
#'org-slideboard-start-slideshow)=, also work in slide windows unless the
show uses the same key.

Emacs's own zoom keys (~C-x C-=~, =C-x C--=, =C-x C-0=, Ctrl+mouse wheel)
change the size of the selected frame during a show, see [[*Text size][Text size]].  To
keep them as plain Emacs zoom, set =org-slideboard-zoom-resizes-frame= to
nil.

** Table of contents
=M-ESC t= lists all slides, including "Title page: …" and "Section: …"
entries, as links.  Clicking a link goes to that slide; =q= closes the list.

** Editing during the show
The column windows show indirect buffers of the presentation file, narrowed
to the column.  Their text is the file's text, so edits made during the show
go straight into the file.

* How slides are displayed

** Layout
- Each slide has a *title strip* at the top, with its heading, and below
  it one or more *frames* (windows, with mode lines hidden):
  - the body of a slide without columns;
  - text between the heading and the first beamer column or code block, in
    a full-width frame;
  - one frame per beamer column, and for code and results (see
    [[*Code and results][Code and results]]).
- Title and section pages use a separate buffer, =*org-slideboard-page*=, with the
  text centred.  If =org-slideboard-animate-pages= is on, the lines are animated
  in; any key press skips the animation.

** Information strip
Every slide has a one-line strip at the bottom, like beamer's footline, with
the author on the left, the title in the middle and the slide number on the
right.  Title and section pages have none.  What it shows is set by
=org-slideboard-footline=, a list of up to three parts, shown left, centre
and right:

#+begin_src emacs-lisp
(setq org-slideboard-footline '("%a" "%t" "%n / %N"))   ; the default
#+end_src

In each part these are replaced; any other text is shown as it is:

| Escape | Replaced by                         |
|--------+-------------------------------------|
| =%t=   | title (=#+TITLE:=)                  |
| =%s=   | subtitle (=#+SUBTITLE:=)            |
| =%a=   | author (=#+AUTHOR:=)                |
| =%d=   | date (=#+DATE:=)                    |
| =%S=   | the section heading above the slide |
| =%h=   | the heading of the slide            |
| =%n=   | number of the slide                 |
| =%N=   | number of slides                    |
| =%%=   | a =%=                               |

Some examples:

#+begin_src emacs-lisp
;; section on the left, date on the right, nothing in the middle
(setq org-slideboard-footline '("%S" "" "%d"))
;; any text
(setq org-slideboard-footline '("Workshop on food balance sheets, Rome" "" "%n / %N"))
;; a part can be a function, called at the slide heading
(setq org-slideboard-footline
      (list "%a" "%t" (lambda () (format-time-string "%H:%M"))))
;; at the top instead
(setq org-slideboard-footline-position 'top)
;; no strip
(setq org-slideboard-footline nil)
#+end_src

For one presentation:

#+begin_example
,#+SLIDEBOARD: footline:("%a" "%S" "%n / %N") footline-position:top
,#+SLIDEBOARD: footline:nil
#+end_example



(In a file, the parts must be strings; functions can only be set in your
configuration.)  The title, author and date are tidied as on the title
page: LaTeX line breaks and commands are removed and macros expanded.  The
strip uses the face =org-slideboard-footline= (grey, a little smaller than
the text) and is not changed by the size keys.

** Images
Image links (=[[file:plot.png]]=) are drawn by org-slideboard with their own
overlays.  Each image is scaled down to at most
=org-slideboard-image-width-fraction= of the window width and
=org-slideboard-image-height-fraction= of its height.

This does not depend on =org-image-actual-width= or other inline image
settings.  An image
file that has changed since it was last shown, e.g. a plot rewritten by a
code block, is read again, so =C-c ;= (or =C-c C-c= in a code window) shows
the new version rather than the one Emacs cached.  When the presentation stops,
the normal Org inline images are shown again.

** Text size
Only the text in the frames of a slide changes size.  Slide titles (the
title strip) and the title and section pages keep theirs:
=org-slideboard-title-text-scale= (2) and =org-slideboard-page-text-scale=
(5).  Text is never shrunk to fit.

All frames of all slides start at =org-slideboard-text-scale= (2, in steps
of =text-scale-mode=).  There are two ways to change it during the show:

| Keys                                         | Changes                                           |
|----------------------------------------------+---------------------------------------------------|
| ~C-=~ / =C--=                                | all frames of all slides                          |
| =C-c }= / =C-c {=                            | the selected frame of this slide only             |
| Emacs zoom: ~C-x C-=~, =C-x C--=, Ctrl+wheel | the selected frame of this slide only             |
| =C-x C-0=                                    | the selected frame back to the common size        |
| =M-ESC 0=                                    | everything back to the size the show started with |

A frame changed on its own keeps its size when you come back to the slide,
and moves with ~C-=~ / =C--=: a frame one step larger stays one step larger
than the others.  Use it for a slide with more text than fits in one of its
frames.  =M-ESC 0= undoes all of it at once: every frame of every slide goes
back to the size the show started with.  Stopping the show does the same,
so the next show starts at the usual size again.  To keep Emacs's zoom
keys as plain zoom, which is lost when the slide is shown again, set
=org-slideboard-zoom-resizes-frame= to nil.  All these keys can be changed,
see [[*Changing the keys][Changing the keys]].

To start every show at another size, set =org-slideboard-text-scale=, or
=#+SLIDEBOARD: text-scale:3= for one presentation (=title-scale:= for
titles).

** Equations
LaTeX math (=$...$=, =\(...\)=, =\[...\]=, =$$...$$= and environments
such as =equation= or =align*=) is previewed as images, as with =C-c C-x
C-l=, and laid out for the slides:

- *Sized to the text*: equations are shown at =org-slideboard-latex-size= (0.8)
  times the size of the text font.  The 10pt LaTeX font is matched to the
  text font by measuring a preview image, so this works with any font,
  with =variable-pitch-mode=, and whatever =:scale= is set in
  =org-format-latex-options=.  Use 1.0 for math as large as the text.
- *Follows the text*: equations grow and shrink with the text when its size
  is changed with ~C-=~ / =C--=.
- *Sharp*: the images are rendered at =org-slideboard-latex-scale= (4.0) and
  displayed smaller.  With =dvisvgm= (SVG) they are sharp at any size; with
  =dvipng= a higher render scale gives sharper but slower images.
- *Left aligned*: display equations start at the left margin, like the
  text.  Set =org-slideboard-center-display-math= to =t= to centre them in the
  window or column, as LaTeX does.  Inline math always stays in the text.
- *Own lines*: display equations inside a paragraph keep their own lines
  when the paragraph is rewrapped.
- *Never wider than the window*: numbered environments such as =equation=
  are as wide as a LaTeX page, since the number is at the right margin, so
  they may be shrunk to fit.  For big equations, use =equation*= or
  =\[...\]=.
- *Named equations*: an environment with a =#+NAME:= line is shown; the
  name line is hidden with the other clutter.
- *No beamer settings in the images*: Org previews equations with the
  article class, but adds the file's =#+LATEX_HEADER:= lines.  Beamer
  commands there, such as =\setbeamersize{description width=0.1cm}=, are
  unknown to article, and LaTeX prints their arguments in every equation.
  During the show, lines matching =org-slideboard-latex-preview-drop-regexp=
  (=\setbeamer...=, =\use...theme=, =\AtBegin...=, =\logo=,
  =\titlegraphic=, =\institute=) are left out of the preview preamble.
  Other headers, such as =\usepackage{amsmath}= or =\newcommand=, are kept.
  Outside the show, =C-c C-x C-l= still uses the full preamble.

When the presentation stops, the equation images are removed, since
they were made for the slides; press =C-c C-x C-l= to preview again.  The
images are cached (in =ltximg/=, see =org-preview-latex-image-directory=),
so a slide is slow only the first time it is shown.

For example, for slightly larger, centred equations in one presentation:

#+begin_example
,#+SLIDEBOARD: latex-size:1.0 center-math:t
#+end_example

** Macros
Org macros (={{{name(arguments)}}}=) are shown on the slides as their
expansion, with overlays, so the file is not changed.  Many macros expand
to LaTeX that means nothing on screen, so a macro can be given a separate
definition for the show.  The expansion is chosen in this order:

1. A =#+SLIDEBOARD_MACRO:= line in the file, written like a =#+MACRO:=
   line.  Beamer and other exporters ignore it.  For example, to show only
   the text of a cell-colour macro:

   #+begin_example
   ,#+MACRO: cc @@latex:\cellcolor{$1}$2@@
   ,#+SLIDEBOARD_MACRO: cc $2
   #+end_example

2. An entry in =org-slideboard-macro-templates=, in the configuration.  The
   template is a string like the above, or a function that gets the
   arguments and returns the text to show, which may have faces.  For
   example, to show the text on a coloured background:

   #+begin_src emacs-lisp
   (setq org-slideboard-macro-templates
         '(("cc" . (lambda (color text)
                     (propertize text 'face `(:background ,color))))))
   #+end_src

3. Org's own expansion, as in export: the =#+MACRO:= definitions and the
   built-in macros (={{{title}}}=, ={{{author}}}=, ={{{date}}}=,
   ={{{time(%Y)}}}=, ={{{n}}}=, ={{{keyword(...)}}}=,
   ={{{property(...)}}}= and so on).  Export snippets for other back-ends,
   such as =@@latex:...@@=, are left out.  The contents of
   =@@slideboard:...@@= snippets are kept, so one =#+MACRO:= line can also
   carry its show version:

   #+begin_example
   ,#+MACRO: cc @@latex:\cellcolor{$1}$2@@@@slideboard:$2@@
   #+end_example

A macro whose expansion is empty (like =cc= above with no show
definition) or that is not defined at all is left as it is, with its
braces hidden (=org-slideboard-hide-macro-markers=).

Expansions are shown as Org text: =*bold*= and =/italic/= in an
expansion look as they do on the slide, and macros inside an expansion
are expanded too.  Macros in =#+TITLE=, =#+AUTHOR= etc. are expanded on
the title page.  =#+MACRO:= definitions that evaluate Lisp (=(eval
...)=) are not expanded, so starting a show never runs code from the
file; use =org-slideboard-macro-templates= for those.  Tables with macros stay
aligned, see [[*Tables][Tables]].

To turn expansion off, set =org-slideboard-expand-macros= to nil (or
=#+SLIDEBOARD: macros:nil=).

** Tables
Org aligns a table by the characters in the file, but on a slide a cell
can show something of another width: an expanded macro, an equation image
(=$\times$=), or text in a proportional font.  During the show, every Org
table is aligned to what is actually displayed: the width of each cell is
measured in the window, and the blanks around it are shown as space of the
right width, so the =|= separators line up.  Numbers, which Org aligns to
the right, stay right-aligned, and horizontal rules are drawn to the column
widths.  This is redone whenever the text size changes.

Only the display changes; the file is not.  To keep Org's own layout, set
=org-slideboard-align-tables= to nil (or =#+SLIDEBOARD: align-tables:nil=).

** Code and results
A slide with a source block can show only the block's results, only its
code, or both.  This is set by =org-slideboard-src-display=:

| Value     | Shows                                                                                |
|-----------+--------------------------------------------------------------------------------------|
| =exports= | what each block's =:exports= says (the default): =code=, =results=, =both= or =none= |
| =results= | only the results of every block                                                      |
| =both=    | the code and the results of every block                                              |

It can be set for the whole presentation, for one file or for one slide (or
all slides of a section, since the property is inherited):

#+begin_example
,#+SLIDEBOARD: src:both

,** Growth of the herd                                                 :slide:
:PROPERTIES:
:SLIDEBOARD_SRC: results
:END:
#+end_example

The drawer is hidden on the slide, and beamer export ignores both.  Blocks
with =:exports none= are always hidden.  Code that is shown is no longer
folded to its =#+begin_src= line.

*** Arranging code and results
With =both=, the first such block of a slide is shown like beamer columns:
text before the block at the top, then the code and the results, with any
text after them, in two windows.  They are arranged by
=org-slideboard-src-split=:

| Value | Code   | Results |
|-------+--------+---------|
| =lr=  | left   | right   |
| =rl=  | right  | left    |
| =tb=  | top    | bottom  |
| =bt=  | bottom | top     |

The value names where the code goes and then where the results go, like
=rankdir= in Graphviz (=LR=, =TB=).  =bt=, the results above the code,
is the default.

It can be set for the whole presentation, for one file, and for one slide
or section with the property =SLIDEBOARD_SRC_SPLIT=:

#+begin_example
,#+SLIDEBOARD: src-split:tb

,** A long plot                                                        :slide:
:PROPERTIES:
:SLIDEBOARD_SRC_SPLIT: tb
:END:
#+end_example

=org-slideboard-src-code-width= (0.5) is the code's share of the width
(side by side) or of the height (top to bottom).  Plots in the results are
scaled to their window.  The code window shows
the whole block, including its =#+begin_src= and =#+end_src= lines.  When
code and results are one above the other (=tb=, =bt=), a thin line in the
face =org-slideboard-divider= separates them; its =:background= sets the
colour and its =:height= the thickness.

*** Code in a beamer column
When a beamer column holds a block to be shown with its results, that
column is divided in two: its text before the block and the code in one
window, and the results with any text after them in the other.  The column
heading can have its own =SLIDEBOARD_SRC= and =SLIDEBOARD_SRC_SPLIT=, e.g. to
show the code of a block exported as results only, with the results below
the code:

#+begin_example
,*** Model                                                              :BMCOL:
:PROPERTIES:
:BEAMER_col: 0.6
:SLIDEBOARD_SRC: both
:SLIDEBOARD_SRC_SPLIT: tb
:END:
#+end_example

=SLIDEBOARD_SRC_SPLIT= (and =src-split:=) only arrange code and results that
are both shown; whether the code is shown at all is set by =SLIDEBOARD_SRC=
(=src:=) or, by default, the block's =:exports=.

Each column is divided on its own, so several columns can each show code
and results.  All windows of the slide get the same text size.

*** Running the code
In the code window, =C-c C-c= runs the block, as it would in Org, and shows
the slide again with the new results, keeping point in the code.  In a
column's code window, which also holds the text before the block, it runs
the block even when point is in that text.  The
results are written to the file as usual.  Running a block of the
presentation any other way during the show also updates the slide.

*** Editing with a REPL
Opening the block for editing in the code window (=C-c '=, or whatever key
runs =org-edit-special=) shows the editing buffer, e.g. ESS R mode, on the
left and a running REPL on the right, where the code can be evaluated with
the usual keys (=C-RET=, =C-c C-c= in ESS; =C-c C-c= in Python mode).

- A block with a =:session= uses that session, in any language.
- A block without one gets the REPL from =org-slideboard-src-repl-functions=:
  ESS R for =R= and =run-python= for =python=, started if not running.
  For ESS, the editing buffer is connected to that R process.

Closing the editor (=C-c '= or =C-c C-k=) shows the slide again, with the
edited code.  The REPLs keep running after the show.  To add a language,
give a function that returns the REPL buffer, e.g. for Julia with the
julia-repl package:

#+begin_src emacs-lisp
(add-to-list 'org-slideboard-src-repl-functions
             '("julia" . (lambda ()
                           (save-window-excursion (julia-repl))
                           (get-buffer "*julia*"))))
#+end_src

** Paragraphs
Line breaks inside a paragraph are displayed as spaces, so hard-wrapped
source text is rewrapped to the column width.  The file is not changed.

** Lists
Lists are laid out with overlays, so the file is not changed:

- *Bullets by depth*: unordered items get the bullets in
  =org-slideboard-list-bullets= by nesting depth, whatever bullet character
  (=+=, =-=, =*=) is used in the file.  The default ='("●" "○" "■" "□")=
  gives =●= for items, =○= for sub-items, and so on, starting again from
  the first for deeper lists.  Numbered items keep their numbers.
- *Indentation*: sub-items are indented by =org-slideboard-list-indent= (4)
  spaces per level, in the text font, so the indentation scales with the
  text and is clear even in proportional text.
- *Wrapped lines*: when an item wraps, the following lines start under
  the item's text, not at the left margin (=org-slideboard-hanging-indent=).

The bullets use the face =org-slideboard-bullet= (the level-1 heading colour,
bold, 1.3 times the text height).  For example:

#+begin_src emacs-lisp
;; arrows and dashes
(setq org-slideboard-list-bullets '("➤" "–" "•"))

;; more indentation per level
(setq org-slideboard-list-indent 6)

;; bigger bullets (in use-package, :custom-face works in any load order)
(use-package org-slideboard
  :custom-face
  (org-slideboard-bullet ((t :inherit org-level-1 :weight bold :height 1.5))))
#+end_src

** Hidden clutter
When =org-slideboard-hide-clutter= is non-nil, the following are hidden:

- drawers: properties, logbook and any others (without Org's "..." in their place)
- =#+NAME:=, =#+RESULTS:=, =#+CAPTION:= and =#+ATTR_*:= lines
- source blocks shown only as results (see [[*Code and results][Code and results]]), and
  blocks with =:exports none=; results, such as plots, stay visible
- =slideboard-elisp= blocks
- standalone raw LaTeX lines such as =\vspace{-0.5cm}= (but not the lines
  of equations, such as =\begin{equation}=)
- blank lines left at the top of a column
- the =:slide:= tag

* Beautification

During the presentation, org-slideboard turns on the minor modes in
=org-slideboard-beautify-modes= in the slide buffers, and hides emphasis and
macro markers.
They are turned off when the presentation stops, unless they were already on
before.  Normal editing is not affected.

The default, ='(org-modern-mode variable-pitch-mode)=, gives:

- styled headings, from [[https://github.com/minad/org-modern][org-modern]]
- larger, coloured list bullets that change with depth: =●= for items, =○=
  for sub-items, then =■= and =□= (=org-slideboard-list-bullets=, face
  =org-slideboard-bullet=); see [[*Lists][Lists]]
- proportional text, from the built-in =variable-pitch-mode=
- =*bold*= shown as *bold* without the asterisks
  (=org-slideboard-hide-emphasis-markers=)
- macros that are not expanded (see [[*Macros][Macros]]) shown without their
  braces, e.g. =cc(red,text)= (=org-slideboard-hide-macro-markers=, which turns
  on =org-hide-macro-markers=)

The bullets replace org-modern's own (small) ones only during the show;
org-modern is unchanged elsewhere.

Some modes are turned *off* during the presentation and back on when it stops:
those in =org-slideboard-disable-modes=, by default =org-indent-mode= (from
=org-startup-indented=), whose heading-level indentation and wrap prefixes
spoil the list layout, and =display-line-numbers-mode=, since line
numbers do not belong on slides.

org-modern's tag labels are turned off during the show, since they would
show part of the hidden =:slide:= tag.

Modes that are not installed are skipped silently.  org-superstar and
org-bullets are not needed with org-modern, which does the same and
more.  org-appear only helps while editing.

** Turning parts of it off
Put any of these in the configuration (or evaluate with =M-:=), then start
the presentation again:

#+begin_src emacs-lisp
;; plain org, no beautification at all
(setq org-slideboard-beautify-modes nil)

;; org-modern only, fixed-width text
(setq org-slideboard-beautify-modes '(org-modern-mode))

;; variable-width text only, no org-modern
(setq org-slideboard-beautify-modes '(variable-pitch-mode))

;; keep the bullets as they are (org-modern's own, if it is on)
(setq org-slideboard-list-bullets nil)

;; keep line numbers during the presentation (only turn off org-indent)
(setq org-slideboard-disable-modes '(org-indent-mode))

;; keep the *, /, = emphasis markers visible
(setq org-slideboard-hide-emphasis-markers nil)

;; keep the {{{ }}} around macros visible
(setq org-slideboard-hide-macro-markers nil)
#+end_src

Note: in variable-pitch text, code blocks can lose their alignment.  Tables
are re-aligned during the show (see [[*Tables][Tables]]).

* Per-file settings

Every setting below can be set globally (e.g. in your init file) and
overridden for one presentation from inside its Org file, in two ways.

** The =#+SLIDEBOARD:= keyword
Put one or more lines like this near the top of the file:

#+begin_example
,#+SLIDEBOARD: modern:nil variable-pitch:t bullets:("➤" "–") image-width:0.7
,#+SLIDEBOARD: animate:nil text-scale:3
#+end_example

The syntax is that of =#+OPTIONS=: =key:value= pairs separated by spaces,
with the values written as Lisp (=t=, =nil=, numbers, strings in double
quotes, lists in parentheses).  The keyword is read each time a show starts,
so changes take effect at the next start.  When the show stops, the previous
values come back.  Beamer and other exporters ignore the keyword.

| Key                 | Setting                                               | Value                                 |
|---------------------+-------------------------------------------------------+---------------------------------------|
| =modern=            | add or remove =org-modern-mode= in the beautify modes | =t= / =nil=                           |
| =variable-pitch=    | add or remove =variable-pitch-mode=                   | =t= / =nil=                           |
| =modes=             | =org-slideboard-beautify-modes=                       | list of =...-mode= symbols            |
| =disable=           | =org-slideboard-disable-modes=                        | list of =...-mode= symbols            |
| =emphasis=          | =org-slideboard-hide-emphasis-markers=                | =t= / =nil=                           |
| =macro-markers=     | =org-slideboard-hide-macro-markers=                   | =t= / =nil=                           |
| =macros=            | =org-slideboard-expand-macros=                        | =t= / =nil=                           |
| =align-tables=      | =org-slideboard-align-tables=                         | =t= / =nil=                           |
| =src=               | =org-slideboard-src-display=                          | =exports= / =results= / =both=        |
| =code-width=        | =org-slideboard-src-code-width=                       | number                                |
| =src-split=         | =org-slideboard-src-split=                            | =lr= / =rl= / =tb= / =bt=             |
| =bullets=           | =org-slideboard-list-bullets=                         | list of strings, or =nil=             |
| =list-indent=       | =org-slideboard-list-indent=                          | number                                |
| =hanging=           | =org-slideboard-hanging-indent=                       | =t= / =nil=                           |
| =title-page=        | =org-slideboard-title-page=                           | =t= / =nil=                           |
| =section-pages=     | =org-slideboard-section-pages=                        | =t= / =nil=                           |
| =animate=           | =org-slideboard-animate-pages=                        | =t= / =nil=                           |
| =page-scale=        | =org-slideboard-page-text-scale=                      | number                                |
| =text-scale=        | =org-slideboard-text-scale=                           | number                                |
| =title-scale=       | =org-slideboard-title-text-scale=                     | number                                |
| =image-width=       | =org-slideboard-image-width-fraction=                 | number                                |
| =image-height=      | =org-slideboard-image-height-fraction=                | number                                |
| =clutter=           | =org-slideboard-hide-clutter=                         | =t= / =nil=                           |
| =latex-size=        | =org-slideboard-latex-size=                           | number                                |
| =latex-scale=       | =org-slideboard-latex-scale=                          | number                                |
| =center-math=       | =org-slideboard-center-display-math=                  | =t= / =nil=                           |
| =footline=          | =org-slideboard-footline=                             | list of up to three strings, or =nil= |
| =footline-position= | =org-slideboard-footline-position=                    | =bottom= / =top=                      |

Unknown keys and invalid values are skipped with a message in the echo
area, and the show starts anyway.  For safety, =modes= and =disable= only
accept symbols whose names end in =-mode=.

** File-local variables
The usual Emacs mechanism also works, with a block at the end of the file:

#+begin_example
# Local Variables:
# org-slideboard-text-scale: 3
# org-slideboard-list-bullets: ("➤" "–")
# org-slideboard-section-pages: nil
# End:
#+end_example

These are read when the file is opened, so after changing the block, re-open
the file (=M-x revert-buffer=).  The simple settings (on/off flags, numbers
and the bullet list) are marked safe, so Emacs does not ask about them.
=org-slideboard-beautify-modes= and =org-slideboard-disable-modes= are not, since a file
could use them to turn on any mode; Emacs asks before using them (answer =!=
to accept a value permanently).

** Precedence
=#+SLIDEBOARD:= overrides a file-local variable, which overrides the global
value.  A size changed with ~C-=~ / ~C--~ during the show changes the value
that is in effect (the local one if there is one).

* Tips

- *Settings*: all options are in the =org-slideboard= customization group
  (=M-x customize-group RET org-slideboard=).  Re-loading the file does not
  reset an option that is already set; use =customize-set-variable=, Customize, or restart
  Emacs.
- *Changing slides during a show*: after adding, removing or
  reordering slides, restart the presentation (or run
  =org-slideboard-initialize=) to rebuild the slide list.
- *Beamer export is unchanged*: the =:slide:= tag is hidden by
  =tags:nil=, and =BMCOL= is handled by ox-beamer as before.
